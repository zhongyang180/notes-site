    RL 算法研究进展调研报告（2025–2026）¶

    调研日期：2026-08-10 关注点：算法层面的创新，以及对我们自己模型训练方法的可迁移启发 配套报告：《verl技术特性调研报告.md》（实操侧）

    0. 摘要¶

    如果只看一句话：2025–2026 年 RL for LLM 的算法创新，主心骨不是"发明新目标函数"，而是围绕 GRPO 这个极简骨架，逐条修掉它的偏置、方差和数值不一致问题。

    几条主线：

    1. critic-free 成为默认。 PPO 的 value model 在长 CoT 场景下又贵又难训，GRPO 用 group 内均值做 baseline 直接绕开。2026 年的主流工具箱（DAPO / GSPO / CISPO / SAPO / Dr.GRPO）全都是 GRPO 家族。
    2. 但 value function 并没有死。 VAPO / VC-PPO 一路证明：只要解决 value 偏置、长度异质、稀疏奖励三件事，value-based 在长 CoT 上仍然能打，且样本效率更高。
    3. 重要性采样（IS）的粒度和裁剪方式成了最活跃的战场。 token-level（GRPO）→ sequence-level（GSPO）→ 软化门控（CISPO / SAPO）。核心矛盾始终是稳定性 vs 探索：硬裁剪丢掉的梯度就是被牺牲的探索。
    4. 训练-推理数值不一致从"工程 bug"升格为"算法问题"。 rollout 引擎（vLLM/SGLang）和训练引擎（FSDP/Megatron）算出的 logprob 不一致，直接违反 IS 假设，是 RL 崩溃的头号元凶。修法有三层：修因（router replay / sampling mask）、修权重（TIS/MIS）、修目标（CISPO）。
    5. 熵坍塌被给出了可操作的定量刻画。 熵与性能存在 R = -a·exp(H) + b 的经验关系，且熵下降主要由"高协方差 token"驱动，于是有了 Clip-Cov / KL-Cov 这类精准干预。
    6. 奖励设计从 rule-based 走向 rubric + generative RM 的混合。 RLVR 覆盖不到的开放域，靠"每个 prompt 自带评分细则"的生成式奖励模型补。
    7. RL 的算力占比在暴涨。 DeepSeek-V3.2 明确写出 RL 预算已超过预训练成本的 10%，且把推理、agent、人类对齐合并成单一 mixed RL 阶段以规避灾难性遗忘。

    对我们最直接的启发，集中在第 10 节。如果时间有限，建议读 §2、§5、§10。

    1. 演化谱系：从 PPO 到 critic-free¶

                        PPO (2017)  ── actor + critic + GAE + clip
                       │
        ┌──────────────┼──────────────────────┐
        │              │                      │
   去掉 critic      保留 critic            完全离线
        │              │                      │
      GRPO          VC-PPO                DPO / IPO / KTO
   (group baseline)  VAPO                (隐式奖励，无采样)
        │
   ┌────┴─────┬──────────┬───────────┬──────────┐
 Dr.GRPO    DAPO       GSPO        CISPO       SAPO
 (去偏置)  (四件套)  (序列级IS)  (软化IS权重) (温度门控)

    三条路径的取舍：

    路径 优点 代价 现状
    PPO + critic 细粒度 credit assignment，样本效率高 多一个模型大小的显存+算力；value 在长 CoT 上偏置严重 小众但未死（VAPO）
    critic-free（GRPO 系） 省一个模型；实现简单；scale 友好 优势估计粗（序列级）；方差大；对 group size 敏感 主流
    纯离线（DPO 系） 最省；无需采样 受限于"不能远离 SFT 策略"；无法自我探索 退化为对齐后处理

    关于纯离线路线的一个重要判断："Learn Your Reference Model for Real Good Alignment" 指出，去掉 reward model 并不等于摆脱了"必须贴近 SFT 策略"这个约束，这是 DPO 系方法的天花板所在。而 Understanding Preference Fine-tuning via Coverage 从 coverage 角度证明了在线 RL 与离线对比方法并不等价，此前认为二者等价的看法（因为起点是同一个偏好数据集）是错的。这解释了为什么工业界最终都回到了在线 RL。？？

    2. GRPO 家族逐条拆解（最核心的一节）¶

    2.0 GRPO 的骨架与它的三个原罪¶

    GRPO 的优势估计：对同一 prompt 采 G 个回答，用组内均值和标准差归一化。

    A_i = (R_i - mean(R)) / std(R)

    三个被后续工作反复攻击的点：

    1. /std(R) 引入难度偏置。 组内方差小（题目太简单或太难）时，除以一个小 std 会把噪声放大，等价于给"接近全对/全错"的题目分配了畸高的梯度权重。
    2. 按序列长度归一化引入长度偏置。 导致错误回答越训越长（模型学会用长度来"稀释"负梯度）。
    3. token-level IS ratio 方差爆炸。 尤其在 MoE 上，单个 token 的 ratio 异常就能污染整条序列。

    2.0.1 第一宗罪的精确形式¶

    难度偏置不需要靠外部图理解，它有闭式解。二元奖励下（对/错），组内标准差完全由通过率 p 决定：

    σ = sqrt(p·(1-p))          梯度权重 ∝ 1/σ = 1/sqrt(p·(1-p))

    把 G=16 的所有可能通过率代进去（p = k/16，k 为组内答对数）：

    组内答对数 k 通过率 p σ = √(p(1-p)) 梯度权重 1/σ 相对 p=0.5 的放大
    0 0.000 0.000 ∞（除零） —
    1 0.0625 0.242 4.13 2.07×
    2 0.125 0.331 3.02 1.51×
    4 0.250 0.433 2.31 1.15×
    8 0.500 0.500 2.00 1.00×（最小）
    12 0.750 0.433 2.31 1.15×
    14 0.875 0.331 3.02 1.51×
    15 0.9375 0.242 4.13 2.07×
    16 1.000 0.000 ∞（除零） —

    这张表就是第一宗罪的全貌，三件事一目了然：

    1. U 型曲线：权重在 p=0.5 处最小，向两端单调上升。"简单题和难题被放大，中等难度题被压制"——而中等难度题恰恰是信息量最大的。
    2. 两端是真正的奇点：p=0 或 p=1 时 σ=0，advantage 变成 0/0。DAPO 的 Dynamic Sampling 本质就是丢掉这两列，它不是在修正偏置，是在回避除零。
    3. 放大倍数取决于 G：G=16 时最极端也只有约 2×，但 G=64 时可以到约 4×（p=1/64 → 1/σ ≈ 8.06，相对 p=0.5 放大 4.03×）。组越大，难度偏置越严重——这点相当反直觉，值得单独记住，因为直觉上会以为加大 G 是在降方差。

    注：上表用总体标准差 √(p(1-p))。若实现用样本标准差（分母 G-1），数值会略大，U 型和奇点的结论不变。

    三种主流做法其实是对同一个数 σ 的三种操作，这个统一视角来自 arXiv 2607.00152（GRPO, Dr. GRPO, and DAPO Are Three Operations on One Number: The Group-Standard-Deviation Identity）：

    2.0.2 第二宗罪：长度偏置（为什么错误回答越训越长）¶

    现象：RL 训练中常见"模型变啰嗦"——回答越来越长，尤其是错误回答膨胀得最快。这不是模型在学深度思考，是 GRPO 归一化项造成的假象。

    根本原因：GRPO 的 per-trajectory 长度归一化。当 loss 按序列平均时：

    loss_per_seq = sum(token_losses) / seq_length

    梯度被长度稀释了。 一条 1000 token 的错误回答，每个 token 分到的负梯度只有 100 token 错误回答的 1/10。模型学到的策略是：既然要错，不如错得长一点，这样每个 token 承担的"惩罚"更小。

    机制拆解（用具体数字说话）¶

    假设两条错误回答（reward = 0），组内其他回答正确（reward = 1）：

    回答 长度 Advantage 每 token 梯度（长度归一化后） 总梯度贡献
    错误回答 A 100 tokens -0.5 -0.5 / 100 = -0.005 -0.5
    错误回答 B 1000 tokens -0.5 -0.5 / 1000 = -0.0005 -0.5

    单个 token 的梯度信号在长回答中被稀释了 10 倍，但模型看到的是每个 token 位置的梯度，而不是序列总梯度。于是产生了畸变的学习信号：长回答里的 token 看起来"没那么错"。

    正反馈循环： 1. 模型生成长错误回答 → 每 token 梯度小 → 这些 token 对应的模式（啰嗦、重复、填充）被抑制得不够 2. 下一轮继续生成类似模式 → 长度进一步增长 3. 正确回答的长度不变，错误回答持续膨胀 → token 效率下降，训练成本上升

    更准确的说法：这是两个问题的叠加¶

    上面的表格把稀释讲成了一个均匀效应——整条序列的信号一起变小。实际情况比这更糟：一条长错误回答里，该背锅的往往只是某一个 token（算错一步、选错公式、引理用反），后面几百个 token 只是在这个错误基础上顺着推。而长度稀释恰恰让这个关键 token 的惩罚被摊薄到几乎为零。

    把它拆成两个独立的失效比较清楚：

    问题 A：advantage 是广播的（credit assignment 失败）

    GRPO 的 A_i 是序列级的一个标量，然后原封不动贴到这条序列的每一个 token 上：

    错误回答: "设 x=5, 代入得 ... [第 47 token: 把 3×7 算成 24] ... 所以答案是 12"
           └── 这段推理其实是对的 ──┘   └─ 真正的错 ─┘   └ 被带偏，无辜 ┘

每 token 的 advantage:  -0.5   -0.5   -0.5  ...  -0.5  ...  -0.5   -0.5
                        ↑ 全部相同，完全分不出谁该负责

    关键 token 和无辜前缀 token 拿到的惩罚一模一样。这跟长度归一化无关——序列只有 10 个 token 也存在。根因是 outcome-only reward：整条轨迹只有"最终答案对错"这一个 bit 的监督信号，中间过程没有任何区分度。

    问题 B：长度稀释（1/L）

    在 A 的基础上，把整体音量再调低 L 倍。

    两者作用在不同的量上，不要混淆：

    关键 token 拿到的份额 关键 token 拿到的绝对量
    理想情况（惩罚集中在出错处） 100% |A|
    GRPO（seq-mean） 1/L（问题 A） |A|/L（A + B 叠加）
    DAPO（token-mean） 1/L（问题 A 未修） |A|（B 已修）

    所以你的直觉是对的，而且可以说得更精确：序列越长，真正出错的那个 token 拿到的惩罚份额越小（1/L），绝对量还要再除一次 L。 它的信号被后面几百个与错误无关的 filler token 一起稀释掉了。反过来说，模型学到"错就错长一点"的另一层含义是——把错误埋在一堆无关文本里，可以有效降低犯错成本。

    三种修法对比¶

    方法 做法 长度偏置 难度偏置 代价
    GRPO 序列级平均 + /std(R) ✗ 有 ✗ 有 —
    Dr.GRPO 去掉两处归一化 ✓ 去掉 ✓ 去掉 引入新的不稳定性（有争议）
    DAPO Token-level Loss mini-batch 全部 token 聚合 ✓ 去掉 ✗ 保留 需配合 Dynamic Sampling 避免 std=0

    Token-level Loss 的精确公式： 

    # GRPO (序列级)
loss = mean([sum(token_losses_seq_i) / len(seq_i) for seq_i in batch])

# DAPO Token-level (直接聚合)
loss = sum([sum(token_losses_seq_i) for seq_i in batch]) / total_tokens

    长度不再出现在分母里 → 长短回答的每个 token 被平等对待。

    一个反直觉的推论：Token-level Loss 不是 credit assignment 的解药¶

    Token-level Loss 只修问题 B，完全不动问题 A。

    去掉 1/L 之后，关键 token 的梯度确实变强了——但那几百个无辜前缀 token 的惩罚也同比变强。总的错误惩罚量反而是增加的：

    seq-mean:    关键 token 权重 1/(N·L)   ← 弱，但无辜 token 也弱
token-mean:  关键 token 权重 1/(ΣL)    ← 强，但无辜 token 同样强

    它做的事情是把音量统一调大，该分不清的还是分不清。这也是为什么 token-level loss 常被观察到"训练更激进、也更容易不稳"——它把长序列的总梯度贡献放大了（长序列贡献 ∝ L，而不再是常数）。

    这不是说不该用 token-level loss——修 B 本身是对的，长度偏置那个正反馈循环确实被切断了。但不要指望它顺带解决"惩罚打在正确位置上"的问题，那需要完全不同的手段。

    但 GRPO 没有想象中那么瞎：共享前缀的梯度会自动相消¶

    这里有个容易被忽略的性质。GRPO 的组内 advantage 是零均值的（Σ_i A_i = 0，这是减去组均值的直接结果）。如果某段前缀在正确和错误 rollout 里逐 token 完全相同，那这段 token 收到的总梯度是：

    Σ_i A_i · ∇log π(a_t | s_t) = (Σ_i A_i) · ∇log π(a_t | s_t) = 0
                               └── 恒为 0 ──┘

    共享前缀的梯度自动抵消，梯度天然集中在 rollout 分叉之后——也就是"错误开始的地方"附近。所以"惩罚应该集中在出错的 token 上"这件事，GRPO 部分地做到了，靠的是组内相消而不是显式建模。这算是 critic-free 方法一个被低估的隐性优势。

    但这个机制很脆弱，别指望它：

    • 只对逐 token 精确相同的前缀成立。实际采样（temperature ≈ 1.0）中 rollout 往往在很早就分叉，真正共享的可能只有开头几个 token
    • 分叉之后即使语义等价、只是措辞不同，也不会相消
    • prompt 部分本来就不计入 loss（被 response_mask 掩掉），所以这个性质只在 response 的共享开头起作用
    • 组内全对或全错时 A_i 全为 0（第一宗罪的奇点），整条序列都没梯度，谈不上相消

    真正修问题 A 的手段¶

    手段 怎么做 报告位置
    Critic + GAE value 网络学到"到第 47 个 token 时状态期望变差了"，给出逐 token 的 advantage §3 VAPO
    过程奖励（PRM） 每个推理步单独打分，不等到最后才给一个 bit 本报告未展开（§7 的奖励设计以 outcome + rubric 为主，工业界公开方案里 PRM 明显退潮，原因见下方边界条件第 2 点）
    GiGPO 双层 group：轨迹级 + step 级，用 anchor state 做同状态相对比较 §8.2

    这正好回答了 §3 里那个判断——为什么"有中间可验证信号的任务应该认真考虑 value-based 路线"。理由就是这个：outcome-only + 广播 advantage 在长序列上注定分不清功过，序列越长越糊。长 CoT 恰恰是序列最长的场景。

    顺带：关键 token 还有第二条受害路径¶

    被长度稀释是一条。同一批关键 token 还会被裁剪直接杀掉——这是 §2.4 CISPO 讲的机制：wait / but / actually 这类低概率反思 token 恰恰最容易让 ratio 冲出裁剪区间，硬裁剪把它们的梯度归零。

    两条路径，同一批受害者：长度归一化让关键 token 声音太小，硬裁剪让它干脆消音。 这两个问题的修法也不同（前者改聚合方式，后者改裁剪方式），但如果你在长 CoT 上训不出反思行为，值得同时查这两处。

    一个边界条件：不要把"错在某个 token"当成普适模型¶

    "从某个 token 开始错"对局部性错误很准（算错一步、选错公式、引理用反），但有两类情况不成立：

    1. 弥散性错误——从一开始就理解错题意，整条链都是错的，不存在"那个 token"。此时广播 advantage 反而是正确的做法
    2. 错了又纠回来——模型第 47 token 算错，第 200 token 反思发现并改对，最终答案正确。这时第 47 token 局部看是错的，但它是有价值的（触发了后面的反思）。按"精确惩罚出错 token"的思路会压制自我纠错能力

    第 2 点尤其值得警惕，它跟 §5 熵坍塌那节能对上：过度惩罚"看起来错"的中间 token，会训出不敢试错的模型。 这也是 PRM 的已知风险之一——step-level 打分容易奖励"看起来规整的推理"而惩罚探索性的弯路。所以问题 A 的修法不是越精细越好，中间过程的监督信号本身也可能是错的。

    2.0.3 第三宗罪：token-level IS ratio 方差爆炸（MoE 的噩梦）¶

    问题的本质：GRPO 在每个 token 位置独立计算 importance sampling ratio：

    ratio_t = π_θ(a_t|s_t) / π_old(a_t|s_t)

    然后用 PPO clip 裁剪每个 ratio。这个做法在密集 transformer（所有 token 走相同路径）上勉强能用，但在 MoE（每个 token 动态路由到不同专家）上会崩。

    为什么 MoE 放大了方差¶

    MoE 的路由不确定性 = 额外的随机源。标准 transformer 里，token t 的输出只依赖： - 输入 x - 模型权重 θ

    MoE 里多了第三项： - 输入 x - 模型权重 θ - 路由决策 r_t（gate 网络选出的 top-k 专家）

    即使权重 θ 只变化一点点（策略更新），路由决策 r_t 可能翻转（从专家 A 跳到专家 B），因为 gate logits 接近时任何扰动都能改变 top-k 排序。

    结果： 

    同一个 token，在 π_old 里走专家 A（输出 logit = 5.2），
              在 π_θ  里走专家 B（输出 logit = -1.3）
→ ratio = exp(-1.3 - 5.2) = exp(-6.5) ≈ 0.0015

    一个异常 ratio 就能污染整条序列，因为 GRPO 把这个 0.0015 直接乘到那个 token 的梯度上，而它可能只是路由抖动而非策略真的变差。

    Token-level vs Sequence-level 的对比¶

    粒度 ratio 定义 方差来源 MoE 友好度
    Token-level（GRPO） ∏_t [π_θ(a_t\|s_t) / π_old(a_t\|s_t)] 每个独立裁剪 每个 token 的 logit 扰动 + MoE 路由翻转 ✗ 崩溃
    Sequence-level（GSPO） [π_θ(y\|x) / π_old(y\|x)]^(1/\|y\|) 几何平均 整条序列的联合概率比 ✓ 稳定

    GSPO 的几何平均 ratio： 

    ρ_seq = (π_θ(y|x) / π_old(y|x))^(1/|y|)
      = exp( (1/|y|) * sum_t [log π_θ(a_t|s_t) - log π_old(a_t|s_t)] )

    单个 token 的异常被 |y| 个 token 的平均值稀释 → 方差降低 |y| 倍（中心极限定理）。

    困惑度视角（更直觉）： 

    ρ_seq = (PPL_old / PPL_θ)    困惑度比的倒数
      = exp(H_θ - H_old)      熵变的指数

    "新策略比旧策略在这条序列上更确定（困惑度更低）" → ratio > 1 → 正向更新。这个解释比 token-level 的乘积清晰得多。

    RSPO 的替代路线（显式建模路由漂移）¶

    GSPO 用粗粒度（序列级）绕过问题，RSPO 用细粒度（per-token）直面问题。

    核心思路：MoE 的 ratio 异常来自路由漂移，那就单独算一个 router-shift ratio，然后把它从 token ratio 里分离出来：

    # 标准 token ratio
r_token = π_θ(a_t|s_t) / π_old(a_t|s_t)

# 路由漂移 ratio（以先前激活的专家为条件）
r_router = p_θ(expert_new | a_t, experts_old) / p_old(expert_old | a_t)

# 校正后的 ratio
r_corrected = r_token / sg(r_router)    # sg = stop_gradient
r_corrected = max(r_corrected, floor)   # 下界 floor，避免负无穷
r_final = softly_rescale(r_corrected)   # 软缩放

    三个技巧： 1. Stop-gradient：路由项不参与主策略的梯度回传，只做权重校正 2. Floor 下界：避免 ratio → 0 导致梯度消失 3. 软缩放：用平滑函数（如 tanh）压缩 ratio 的动态范围

    代价：需要存储每个 token 的路由决策（experts_old），显存和计算量都比 GSPO 大。

    监控这四个分布（每 N 步记录一次 histogram）：

    2.1 Dr.GRPO — 去掉两个偏置项¶

    论文：Understanding R1-Zero-Like Training: A Critical Perspective（COLM 2025，sail-sg） 代码：sail-sg/understand-r1-zero

    发现的问题： GRPO 存在一个优化偏置，会人为地拉长回答长度，尤其是错误回答的长度。这正是社区里常见的"RL 训着训着模型变啰嗦"现象的算法根源——它不是模型在"学会深度思考"，而是归一化项造成的假象。

    修法： 去掉两处归一化 - 去掉优势的 /std(R)（消除难度偏置） - 去掉 per-trajectory 的长度归一化（消除长度偏置）

    收益： 在保持推理性能的同时显著提升 token 效率（更短的回答拿到同样的分）。

    注意一个争议： 一篇 2026 的工作 论证了「无偏」与「长度不变」这两个性质在 outcome reward 下不可能同时满足，并指出 Dr.GRPO 声称的无偏是有条件的。另有分析认为 Dr.GRPO 去掉归一化后引入了新的不稳定性和 verbosity bias（MAD-GRPO 讨论）。所以这不是一个"直接抄就赢"的改动，需要自己跑 ablation。

    2.2 DAPO — 四件套，工程上最实用¶

    论文：DAPO: An Open-Source LLM RL System at Scale（ByteDance Seed × 清华 AIR） 成绩：Qwen2.5-32B base 上 AIME 2024 达到 50 分（后续 verl 官方复现到 52 分）

    四个技巧，每一个都可以独立拆下来用：

    技巧 解决什么 做法
    Clip-Higher 熵坍塌 / 低概率 token 无法成长 解耦上下裁剪边界，ε_low=0.2, ε_high=0.28。上界放宽让低概率 token 有上升空间
    Dynamic Sampling 全对/全错的组梯度为零，浪费算力 过滤掉组内 reward 全同（std=0）的组，继续采样直到填满 batch
    Token-level Loss 长回答里的 token 被稀释 loss 在 mini-batch 全部 token 上聚合，而非先按序列平均
    Overlong Reward Shaping 截断样本给出错误的负信号 在硬截断上限之下设一个缓冲区（4096 token），惩罚线性渐增而非断崖

    Clip-Higher 是我认为性价比最高的单点改动——一行配置，直接缓解熵坍塌。

    一个值得注意的细节：DAPO 论文里的 "Overlong Filtering" 在 verl 官方实现里故意没做，理由是它与 Overlong Reward Shaping 功能重叠。

    2.3 GSPO — 把 IS 提到序列级¶

    论文：Group Sequence Policy Optimization（Qwen 团队） 博客：GSPO: Towards Scalable RL for Language Models

    核心洞察：奖励是序列级的，IS 权重却是 token 级的——这个粒度不匹配本身就是方差来源。

    GSPO 把重要性比定义在序列似然上，并在序列级做裁剪和优化：

    ρ_seq = (π_θ(y|x) / π_old(y|x))^(1/|y|)      # 长度归一化的序列级 ratio

    最重要的实证结论：GSPO 显著稳定了 MoE 的 RL 训练。 这一点对我们如果要训 MoE 是关键信息——MoE 的 routing 是离散 top-k 决策，训练/推理间微小数值差异会翻转部分路由决策，逐层累积后大部分 token 被路由到不同专家，token-level IS 假设直接崩掉。GSPO 用序列级 ratio 对这种局部扰动更鲁棒。

    Qwen3 系列的训练用的就是这套。论文还提到 GSPO 有"简化 RL 基础设施"的潜力（因为对数值不一致更宽容，可以少做很多对齐工作）。

    它的代价： 一条序列里只要有几个强 off-policy 的 token，GSPO 就会把整条序列的梯度全部压制。这是 SAPO 要修的点。

    2.4 CISPO — 裁权重，不裁更新¶

    论文：MiniMax-M1: Scaling Test-Time Compute Efficiently with Lightning Attention 参考实现：NeMo-RL CISPO 走读、torchrl CISPOLoss

    核心区别：PPO/GRPO 的硬裁剪会让被裁 token 的梯度直接变成 0；CISPO 改为把 IS 权重作为一个 detach 的系数来裁剪，梯度依然存在，只是被缩小。

    # GRPO：ratio 出界 → 该 token 梯度归零（信息彻底丢失）
# CISPO：clip(ratio).detach() 作为系数 → 梯度保留方向，只压幅度
L = - E[ sg(clip(ρ_t, 1-ε, 1+ε)) · A · log π_θ(a_t) ]

    为什么这很重要： 在长 CoT 里，那些 ratio 出界的 token 往往恰恰是关键的转折 token（"wait"、"but"、"actually" 这类引发反思的低概率词）。硬裁剪把它们的梯度扔掉，等于系统性地压制了反思行为的学习。

    MiniMax-M1 靠 CISPO + hybrid attention 在 512 张 H800 上完成了全量 RL 训练。verl 0.7 已内置 CISPO。

    2.5 SAPO — 软自适应门控¶

    论文：Soft Adaptive Policy Optimization（Qwen 团队，2025-11）

    问题定位： 硬裁剪造成"稳定性 vs 有效学习"的二选一；GSPO 的序列级压制粒度太粗。

    做法： 用一个平滑的、温度控制的门控替代硬裁剪，自适应地衰减 off-policy 更新。论文自称同时具备 "sequence-coherent and token-adaptive" 两个性质——序列层面保持一致性，token 层面又能区别对待。

    与 GSPO 的直接对比（论文自己给的场景）： 一条序列里有几个强 off-policy token 时，GSPO 压制整条序列的所有梯度，SAPO 只降权那几个 token，保留近 on-policy 部分的学习信号。

    应用：Qwen3-VL 系列就是用 SAPO 训的。 verl 0.7 已内置。

    2.6 其他值得关注的变体¶

    方法 一句话 来源

    3. value-based 路线并未死：VAPO¶

    主流叙事是"critic 太贵，扔了吧"，但 ByteDance Seed 的 VAPO 给出了反例。

    VAPO（Value-based Augmented PPO）的论点：value-based RL 在长 CoT 上仍然可行且更优，前提是解决三个具体问题：

    1. value model 偏置 —— 用 value pretraining 解决（来自 VC-PPO）
    2. 序列长度异质性 —— 用 decoupled GAE 解决（对 value 和 policy 用不同的 λ）
    3. 稀疏奖励信号 —— 借用 DAPO 的 clip-higher + token-level loss

    报告成绩：Qwen2.5-32B base 上 AIME 2024 约 60 分（高于 DAPO 的 50）。

    注：本条主要基于既有认知，本次调研的搜索未能直接命中 VAPO 原文，建议正式引用前用 "VAPO ByteDance Seed arxiv" 单独检索确认数字。

    对我们的启发： 如果我们的任务有密集/中间可验证信号（比如多步工具调用，每步都能判对错），value-based 的细粒度 credit assignment 优势会比在纯数学题上明显得多。不要因为"社区都用 GRPO"就默认放弃 critic。

    decoupled GAE 这个技巧本身值得单独借鉴——policy 需要低偏置（λ 接近 1），value 需要低方差（λ 更小），用同一个 λ 本来就是妥协。

    4. 训练-推理不一致：本轮最被低估的问题¶

    这一节我认为是整份报告里对工程落地最重要的部分。

    4.1 问题本质¶

    RL 训练里有三个策略，很多实现却只认两个：

    • π_rollout —— 推理引擎（vLLM/SGLang）实际采样用的策略
    • π_old —— 训练引擎重新前向算出的"旧策略"
    • π_θ —— 当前正在更新的策略

    常见错误：把 π_old 当作行为策略，完全忽略 π_rollout 的存在。 但两者在数值上并不相等，来源包括：

    • 精度差异（FP8/BF16、不同 kernel 实现）
    • 后端差异（vLLM 的 paged attention vs Megatron 的实现）
    • MoE routing 翻转（最严重）
    • top-p / top-k 截断造成的动作空间不一致
    • 异步训练里的 stale checkpoint

    verl 文档对此的表述很到位："This is not PPO's fault - PPO itself is mathematically correct." 错的是那个假设，而它会直接导致训练崩溃。

    4.2 三层修法¶

    第一层：修因（最彻底）

    • Router Replay（MoE 必备） —— 记录 rollout 时每个 token 实际选择的专家，训练时强制复用同一路由路径，绕过实时路由计算。DeepSeek 称之为 "keep routing"，并明确说这是 MoE RL 稳定性的关键，且从 DeepSeek-V3-0324 起就在用。现已成为 Megatron Core 一等公民特性，verl 0.7 有 vLLM 的实验性 router replay。
    • Keep Sampling Mask —— rollout 时的 top-p/top-k 截断改变了动作空间，使 π_old 与 π_θ 的支撑集不同，IS 假设失效。DeepSeek 的做法是把截断 mask 持久化，训练时同样施加，让两个策略共享同一动作子空间。他们提到这一招配合 top-p 还改善了 RL 过程中的语言一致性。

    第二层：修权重（TIS / MIS）

    Truncated Importance Sampling —— 用 π_θ/π_rollout 的比值做重加权，并做上截断：

    w = exp(clamp(log_ratio, -20, 20)).clamp(max=threshold)

    关键设计：只截上界不截下界，因为"这保留了小权重情形下的无偏性"。verl 提供了完整的方法族（见实操报告 §4）：Token-TIS、Seq-TIS、Seq-MIS、Geo-RS、K3-RS、IcePop。

    第三层：修目标函数

    让 loss 本身对坏 IS 权重不敏感——这就是 CISPO（detach 系数）和 GSPO（序列级 ratio）在做的事。

    第四层（数据侧兜底）：序列掩码

    丢掉 train/rollout logprob 偏差超阈值的序列。DeepSeek 的做法有个精妙细节：只对负优势序列施加掩码。理由是"模型从自己的错误中学得最好，但过于 off-policy 的负样本会误导优化"。NVIDIA Nemotron 的做法是设 seq_logprob_error_threshold: 2。

    代价是丢数据，用样本效率换稳定性。

    4.3 一个必须记住的实证结论¶

    verl 的 FP8 实验给出了这份报告里最有操作价值的单条数据：

    Qwen3-8B-Base 上做 FP8 rollout，开了 token-level TIS 时精度与 BF16 齐平；不开 TIS 时有"明显的精度下降"。

    也就是说：低精度 rollout 的加速红利，是靠 IS 校正才能安全兑现的。 想上 FP8 省成本，就必须同时上 rollout correction，两者是配套的。

    5. 熵坍塌：从现象到可操作的干预¶

    5.1 定量刻画¶

    论文：The Entropy Mechanism of RL for Reasoning Language Models

    三个层次的结论：

    1. 现象： 不做熵干预时，策略熵在训练早期急剧下降，策略变得过度自信，探索能力消失，性能随之饱和。
    2. 定量关系： 拟合出 R = -a·exp(H) + b。熵是性能的上限——熵一旦耗尽，性能就锁死了。这个公式的实用价值在于：看着熵曲线就能预判性能天花板，不必等跑完。
    3. 机制： 熵的变化量与「token log-prob 和其 advantage 的协方差」直接相关。高协方差 token 是把熵推下去的元凶。

    5.2 两种精准干预¶

    既然定位到了元凶，干预就可以很精准（都只作用于高协方差 token）：

    • Clip-Cov —— 对高协方差 token 裁剪更新
    • KL-Cov —— 对高协方差 token 施加 KL 惩罚

    verl 已内置，脚本在 recipe/dapo/7b_kl_cov.sh 和 32b_kl_cov.sh。

    效果（7 个数学 benchmark 平均）：

    模型 GRPO Clip-Cov KL-Cov
    Qwen2.5-7B 38.6 40.4 40.6
    Qwen2.5-32B 45.8 50.3 52.2

    两个值得注意的点：模型越大收益越大（32B 上 +6.4 分），且在 AIME24/25 这类难题上增益更明显。KL-Cov 能让熵在 baseline 已经躺平后仍维持高出约一个数量级的水平。

    5.3 另一种解释：裁剪边界才是主因¶

    Clip-Low Increases Entropy and Clip-High Decreases Entropy 给出了一个不同的归因：熵动力学主要由 PPO 裁剪边界的不对称性决定，而非协方差。

    它的结论很有冲击力：clip-low 推高熵，clip-high 压低熵；在标准裁剪参数下 clip-high 占主导，以至于即使 reward 完全随机，熵也会下降。

    这与 DAPO 的 Clip-Higher（放宽上界 → 抑制熵坍塌）在方向上完全一致，算是互相印证。另有 Rethinking Entropy Interventions in RLVR 系统性重审了整个干预设计空间。

    实操建议： 熵干预有三个层次的手段，成本递增——先调 clip_ratio_high（一行配置），不够再上 KL-Cov，最后才考虑显式熵正则（entropy_coeff，容易训崩，慎用）。

    6. RL 到底有没有扩展推理边界？¶

    这是一场还没打完的仗，但它决定了我们该给 RL 分配多少算力。

    6.1 悲观派¶

    原始论点来自 Yue et al.《Does RL Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?》：RL 训练后的模型在高 k 的 pass@k 上反而不如 base model——RL 只是把概率质量集中到 base model 已有的正确路径上，是"锐化"而非"扩展"。

    支撑证据：只看正确率的 RLVR 会造成多样性坍塌，生成结果向少数几种实现方式聚集（arXiv:2605.28022）。还有工作用 spurious reward 作探针，论证 RLVR 可能激活的是记忆捷径而非推理（arXiv:2601.11061）。

    6.2 乐观派¶

    ProRL（NVIDIA） 是最有力的反驳：ProRL: Prolonged RL Expands Reasoning Boundaries（NeurIPS）。核心论点是——之前的悲观结论是因为训得不够久。 长时间 RL 能挖出 base model 即使大量采样也到不了的推理策略。

    后续工作： - ProRL v2 —— 持续 RL，1.5B 量级 SOTA（NVIDIA blog） - BroRL —— 换一个轴：不加步数，而是加每步的 rollout 数（NVIDIA blog） - 还有工作从理论上论证 RLVR 相对 SFT 在 inference-time compute 上存在指数级分离（arXiv:2606.22938）

    DeepSeek-V3.2 用真金白银站在乐观派：RL 预算超过预训练成本的 10%，并把推理能力提升主要归因于这个 scaling。

    6.3 我的判断与对我们的启发¶

    两派其实不矛盾，分歧在于训练时长和探索保持：

    • 短程 RL + 无熵干预 → 确实是锐化，pass@k 会退化
    • 长程 RL + 熵/多样性维护 → 能扩展边界

    可操作的三条：

    1. 必须同时监控 pass@1 和 pass@k。 只看 pass@1 会让你误以为在进步，实际上多样性正在崩。这是最容易踩的坑。
    2. 别过早停止 RL。 ProRL 的教训是很多人在收益出现前就停了。
    3. 把多样性写进目标。 已有工作显示 pass@k-aware 的目标能同时改善 pass@1 和 pass@k（arXiv:2509.26209）。

    7. 奖励设计：从 rule-based 到 rubric + 生成式 RM¶

    算法目标函数改得再精巧，也超不过奖励信号的质量上限。这一节是 2026 年真正的增量所在。

    7.1 分层的奖励体系¶

    以 DeepSeek-V3.2 的设计为参照（这是目前公开信息最完整的工业级方案）：

    任务类型 奖励来源
    推理 / agent rule-based outcome reward + 长度惩罚 + 语言一致性奖励
    通用开放域 生成式 RM，且每个 prompt 自带评分细则（rubrics）
    agentic search 混合：可验证 QA 对 + rubric 打分的生成式奖励（同时管事实性和有用性）
    code agent 执行结果：只有当 gold patch 产生非零 fail-to-pass 测试且零 pass-to-fail 回归时，环境才算有效
    通用合成 agent 任务 自带 Python verifier 函数，奖励完全程序化

    "每个 prompt 自带 rubric" 是我认为最值得抄的一点。 通用的 RM 打分必然模糊，而针对单个 prompt 生成的评分细则能把开放域任务转化为准可验证任务。OpenAI 的 Argo 从另一个方向印证了这条路——它把 rubric 构造建模为搜索问题：找到一组 rubric，使得 rubric-conditioned 的 LLM judge 能复现黑盒 RM 的偏好概率。

    7.2 分阶段的 KL 策略¶

    NVIDIA Nemotron 的做法揭示了一个容易忽略的实践细节：不同奖励类型的 RL 阶段应该用不同的 KL 强度。

    • RLVR 阶段、SWE-RL 阶段：KL = 0（可验证奖励，不怕跑偏，放开探索）
    • RLHF 阶段：KL = 1e-4（主观奖励，需要约束防 reward hacking）

    且 Nemotron 把 RLHF 放在最后，在 RLVR 和 SWE-RL 之后，专门用于调行为和交互质量。这是对原始单阶段 RLHF 框架的重要修正：能力靠可验证奖励 RL 拿，风格和体感靠 RLHF 收尾。

    DeepSeek 的补充：KL 强度还应按 domain 分别调，数学任务可以用很弱的 KL 甚至不用。

    7.3 reward hacking 的防线¶

    NeurIPS 2024 有两篇从不同角度打 reward over-optimization：

    • 信息论 RM 框架（InfoRM） —— 针对 reward misgeneralization，即 RM 抓住了与真实人类偏好无关的伪特征，并带 over-optimization 检测机制（paper）
    • 隐状态正则化 —— 报告在 OOD 任务上 RM 精度更高，over-optimization 减少（paper）

    两篇指向同一个结论：约束不在优化器，而在 RM 的泛化能力上。 这个判断很重要——它意味着与其反复调 policy 优化算法，不如投入到 RM 质量上。

    另外提一句安全面：把人类判断作为奖励信号会引入投毒和操纵的攻击面。如果我们要建反馈收集 pipeline，标注输入应当按不可信数据处理。

    7.4 单阶段 mixed RL vs 多阶段¶

    DeepSeek-V3.2 明确选择把推理、agent、人类对齐合并进单一 RL 阶段，理由是"规避多阶段设置的灾难性遗忘问题"。

    这与 Nemotron 的多阶段路线（RLVR → SWE-RL → RLHF）正好相反。两条路线都有成功案例，取舍点在于： - 单阶段：需要精细的 domain 配比和 per-domain KL，实现复杂但无遗忘 - 多阶段：实现简单，但后阶段会侵蚀前阶段的能力

    给我们的建议： 如果 domain 数量少（2-3 个），多阶段够用且好调；如果要同时管推理+agent+对齐，单阶段 mixed RL 更安全，但要做好 domain 采样配比的基础设施。

    8. Agentic RL：多轮与长程 credit assignment¶

    这是算法上仍然开放、也最可能出增量的方向。

    8.1 核心难点¶

    1. 稀疏 outcome reward + 跨轮 credit assignment —— 一个 20 步的 agent 轨迹最后只有一个成败信号，怎么知道是第几步错的
    2. 轨迹长度方差极大 —— 有的任务 2 轮结束，有的 50 轮，batch 内极度不均衡
    3. 环境交互的长尾 —— 少数慢样本拖垮整个 batch（这是系统问题，见实操报告 §5）
    4. tool response token 不该算 loss —— 需要精确的 response mask

    8.2 代表工作¶

    方法 思路
    GiGPO (Group-in-Group) 双层 group：轨迹级 + step 级，提供 anchor state 级别的相对优势，缓解 credit assignment。verl-agent 是官方实现
    MT-GRPO + GTPO 多轮 GRPO 配合 generalized token-level policy optimization，加迭代式 reward calibration（arXiv:2604.02869）
    SkyRL-Agent 异步 dispatch + 轻量工具集成，专攻长程 agent（arXiv:2511.16108）
    Rollout-as-a-Service 把 rollout 拆成独立服务，解决多轮环境交互的伸缩问题（arXiv:2603.18815）
    Orchestration Traces RL 面向多 agent 系统，不只优化单个动作，还优化任务如何 spawn/delegate（arXiv:2605.02801）

    8.3 一条重要的工程警告¶

    verl 文档里记录了一个坑，值得单独拎出来：不要用 chat completion 的 message 历史重新 apply chat template 来构造训练 token。

    原因有两条： 1. tool parser 会改写 content —— assistant content 里的 <tool_call> 块被抽取成结构化的 tool_calls 字段，重新编码后 token id 与原始生成的不一致 2. decode-then-encode 往返本身就会引入不匹配

    后果：轨迹偏离了策略模型的真实分布。 verl 报告说即使在单轮情况下，用最终 message 历史 apply chat template 会导致 PPO 完全不收敛。

    正确做法是 token-in/token-out，或者用 delta-based tokenization（只对增量部分编码）。这个坑很隐蔽——它不会报错，只会让训练悄悄不收敛。

    8.4 评测的可复现性警告¶

    On Effectiveness and Efficiency of Agentic Tool-calling and RL Training 指出：agent 工具调用的评测结果对看似微小、且常常没被记录的实现选择极度敏感。

    这意味着跨论文的 agent benchmark 数字基本不可直接比较。我们自己做评测时，需要把 prompt 模板、tool schema、parser 实现、最大轮数这些都固化下来。

    9. 另一条路：on-policy 蒸馏¶

    这是 2025 年底冒出来的一条值得关注的支线。

    Thinking Machines 的论点（On-Policy Distillation）：

    • RL 的优势：学生从自己访问到的状态中学习，直接修正自己的错误
    • RL 的致命弱点：反馈极度稀疏——不管用了多少 token，每个 episode 只教会固定的几个 bit
    • SFT 的弱点：学的是专家轨迹，但从没学会从自己的错误中恢复

    on-policy 蒸馏结合两者：学生自己采样（on-policy），但用教师模型提供 token-level 的密集监督（而非只有最终奖励）。宣称训练成本可降 30 倍（报道）。

    后续研究的补充与警告：

    • OPD 主要学到的是"思维模式" 而非新知识（arXiv:2604.13016，thunlp/OPD）
    • privileged teacher 反而有害 —— 用带特权上下文的教师做自蒸馏，会让模型产生更少的验证、回溯、犹疑标记，即使做了长度归一化（arXiv:2607.05184）。这条挺反直觉：给教师更多信息，学生学到的推理反而更浅
    • OPSD 更适合定位为 RLVR 之后的压缩阶段，而非 RLVR 的替代（arXiv:2605.06188）
    • Reopold —— 标准 on-policy 蒸馏会因过度模仿教师而不稳定，需要"放松"（arXiv:2603.11137）

    对我们的启发： 如果手上有一个明显更强的同族大模型，on-policy 蒸馏的信号密度优势（每 token 都有监督 vs 每 episode 一个标量）是 RL 比不了的，性价比很高。但要清楚它的定位是能力压缩/迁移，不是能力扩展——扩展边界还得靠 RL。verl 已内置 algo/opd（on-policy distillation）和异步 on-policy 蒸馏 recipe。

    10. 对我们模型训练的具体启发¶

    按"投入产出比"排序，这是整份报告我最想传达的部分。

    第一梯队：几乎零成本，建议立刻做¶

    1. Clip-Higher（一行配置）

    actor_rollout_ref.actor.clip_ratio_low: 0.2
actor_rollout_ref.actor.clip_ratio_high: 0.28

    抑制熵坍塌最便宜的手段，DAPO 已验证。

    2. 开启 rollout correction 的监控（先只看不改）

    actor_rollout_ref.rollout.calculate_log_probs: true
algorithm.rollout_correction: { rollout_is: null, rollout_rs: null }

    先测量 rollout_corr/kl、log_ppl_abs_diff、chi2_token，搞清楚我们的训练-推理 gap 到底有多大。在不知道 gap 大小的情况下调其他超参，等于在噪声上做优化。 开销只有 ~1% 显存、1-3% 算力。

    3. 同时监控 pass@1 和 pass@k

    防止多样性坍塌被 pass@1 的假性提升掩盖。这是纯监控成本。

    4. 熵曲线 + R = -a·exp(H) + b

    拟合一下就能预判性能天花板，不必等训完。

    第二梯队：明确收益，需要少量工作¶

    5. Dynamic Sampling（过滤全同 reward 的组）

    全对/全错的组梯度为零，纯浪费算力。DAPO 用 gen_batch_size=1536 / train_batch_size=512 的超采样比。

    6. loss_agg_mode 选 token-mean

    Dr.GRPO 和 DAPO 一致推荐，消除长度偏置。verl 默认值就是这个，但要确认没被改掉。

    7. Overlong Reward Shaping

    截断样本给出的负信号是错的（模型没答错，只是没写完）。设 4096 的缓冲区做线性惩罚。

    8. KL-Cov（如果熵坍塌确实是瓶颈）

    32B 上 +6.4 分是很实在的收益，且模型越大越明显。verl 有现成脚本。

    第三梯队：需要判断，取决于我们的具体场景¶

    9. 如果训 MoE → Router Replay 是必需品，不是可选项

    DeepSeek 从 V3-0324 就在用，且明确说是 MoE RL 稳定性的关键。同时考虑 GSPO 的序列级 IS。这两条都是针对 MoE 的，普通 dense 模型可以不管。

    10. 如果想上 FP8 rollout → 必须同时上 TIS

    verl 的实验很明确：不开 TIS 会有明显精度下降。收益：dense 约 12-18% rollout 加速，MoE 超过 35%。

    11. 如果任务有中间可验证信号 → 认真考虑 value-based（VAPO 路线）

    多步工具调用这类场景，细粒度 credit assignment 的价值远高于纯数学题。别因为社区都用 GRPO 就默认放弃 critic。decoupled GAE 这个技巧可以单独拿来用。

    12. 奖励设计投入 > 算法投入

    如果我们的 RM 质量是瓶颈（NeurIPS 那两篇的判断是"约束在 RM 泛化而非优化器"），那再换十个 *PO 都没用。优先考虑： - 每个 prompt 自带 rubric 的生成式 RM - 分阶段差异化 KL（RLVR 用 0，RLHF 用 1e-4） - 长度惩罚 + 语言一致性奖励（DeepSeek 的标配）

    13. 如果有更强的同族模型 → on-policy 蒸馏做能力压缩

    信号密度优势明显，但定位是压缩不是扩展。

    明确不建议做的¶

    • 再造一个 *PO。 这个方向边际收益已经很薄，命名空间都快枯竭了。
    • 过早停止 RL。 ProRL 的教训。
    • 用 message 历史 apply chat template 构造训练 token。 会静默地不收敛。
    • 只看 pass@1 做决策。
